# 물 마시기 앱 (drinkWaterApp)

물을 마실 때마다 내 화분에 물을 주고, 그 화분을 키우고 꾸미는 **수분 섭취 습관 앱**.
기록하는 행위 자체에 즉각적인 시각 보상(식물이 자라고 꽃이 핀다)을 붙여, "기록은 되는데 계속 열지 않는" 기존 물마시기 앱의 이탈 문제를 푸는 것이 목표다.

> 앱 이름은 가칭 "물마시GO"이며 확정 전이다. (기획서 13장 #1)

| 항목 | 내용 |
|---|---|
| 플랫폼 | Android, iOS (Flutter 단일 코드베이스) |
| 1차 타겟 | 20~30대 여성, 건강 관리·꾸미기 요소에 호감이 높은 층 |
| 사용 맥락 | 하루 5~10회, 한 번에 3~10초. 앱 실행부터 기록 완료까지 2탭 이내 |
| 백엔드 | **MVP(1.0)는 서버 없음.** 모든 데이터는 기기 로컬 DB에 저장 |
| 핵심 검증 지표 | D7 리텐션 25% 이상 (이 수치가 나오기 전에는 수익화를 진행하지 않음) |
| 문서 | [기획서 v1.4](docs/기획서_v1.4.md) · [UI 시안](docs/design/UI_시안.pdf) |

## 현재 상태

기획서에 정의된 6개 화면과 핵심 로직의 코드 작성을 마쳤다. **다만 아직 실기기·에뮬레이터에서 실행해 본 적은 없다.**
(Android·iOS 플랫폼 폴더를 만들고 알림용 네이티브 설정까지 넣었지만, 검증은 분석·테스트와 Android 디버그 빌드까지만 했다. iOS 빌드는 아직 확인하지 못했다.)

## 저장소 구조 (모노레포)

```
├── app/        # Flutter 앱 (MVP는 서버 없이 로컬 DB만 사용)
├── docs/       # 기획서, UI 시안
├── backend/    # P3(소셜·클라우드 백업) 도입 시 추가 예정 (후보 정리만 있음)
└── .github/
    └── workflows/ci.yml   # 분석 + 테스트

앱 내부는 **Feature-first + 3계층(data / domain / presentation)** 이다.

```

├── core/
│   ├── config/        # AppConfig: 서버·외부 도구 설정 (--dart-define)
│   ├── database/      # Drift 테이블, 앱 DB, 아이템 마스터 시드, enum 변환기

│   ├── home/          # S2  물 기록 저장소, 상한·연타 규칙, 화분 영역

## 핵심 규칙 요약

기획서의 주요 규칙 중 코드에 반영된 것만 간단히 정리한다. 자세한 내용은 [기획서](docs/기획서_v1.4.md) 5장 참고.

- **목표 음수량**: `체중(kg) × 33ml × 성별보정 × 연령보정`을 50ml 단위로 반올림, 1,000~3,500ml로 제한. 직접 입력은 500~4,000ml(10ml 단위). 의학 조언이 아니라는 고지를 온보딩·설정에 상시 표시한다.
- **기록 단위**: 사용자는 "컵"(종이컵 200 / 머그컵 300 / 텀블러 500 / 기타 350ml, 용량 수정 가능)으로 고르고, 데이터는 항상 ml로 저장한다. 묶음 기록은 컵 용량씩 분리 저장한다.
- **하루 상한**: 4,000ml 또는 30회. 넘는 기록은 저장하지 않는다.
- **연타 방어**: 기록 직후 1.2초 쿨다운(탭 무시), 60초 안에 3회 기록 후 4회째는 확인 시트. 어뷰징은 막기보다 이득을 없앤다(해금은 전부 "일수" 기준).
- **스트릭**: 목표 100% 달성 시 하루 1회 +1. 전날 미달성이면 자정 전환 시 0으로 초기화, 최고 기록은 유지.
- **하루의 경계**: 기기의 로컬 시간 00:00. 백그라운드에서 자정을 넘긴 뒤 복귀해도 날짜를 다시 검증한다.
- **꾸미기**: 위치·크기는 고정이고 아이템 교체만 가능. 모든 얼굴 부위는 식물이 아니라 화분(용기) 기준 앵커에 놓여 성장 단계가 바뀌어도 어긋나지 않는다.
- **데이터 보존**: 서버가 없으므로 앱 삭제 시 데이터가 사라진다. 이를 보완하려고 설정에서 JSON 백업·복원을 제공한다.

## 시작하기

사전 준비: Flutter SDK (CI는 stable 채널 사용, 현재 3.47.6으로 확인). Android 빌드에는 Android SDK, iOS 빌드에는 macOS와 Xcode가 필요하다.

```bash
cd app
flutter pub get
flutter gen-l10n                                  # 문구 코드 생성
dart run build_runner build                       # Drift 코드 생성
flutter run
```

- 생성 파일(`*.g.dart`, `app_localizations*.dart`)은 `.gitignore` 대상이라 위 명령으로 만든다.
- 플랫폼 폴더는 이미 생성되어 있다. 번들 ID는 임시값(`com.example.drink_water_app`)이므로 확정되면 바꾼다.
- 알림용 네이티브 설정은 이미 들어 있다. 내용은 [app/README.md](app/README.md)의 "알림 플랫폼 설정" 참고.

### 검증

```bash
cd app
flutter analyze
flutter test
```

CI(`.github/workflows/ci.yml`)가 같은 순서로 push와 `main` 대상 PR마다 실행하고, 별도 작업으로 `flutter build apk --debug`까지 확인한다(iOS 빌드는 아직 CI에 없음). 테스트는 14개 파일, 107개 케이스이며 DB 스키마, 권장량 계산, 물 기록 규칙(상한·스트릭·되돌리기), 통계 집계, 설정·백업, 꾸미기 규칙을 다룬다.

### 환경 설정 (서버·외부 도구)

MVP는 서버 없이 동작하므로 **설정하지 않아도 실행된다.** Supabase·API 서버·Firebase 연동 플래그를 붙일 때는 [`app/config/README.md`](app/config/README.md)를 참고한다. 앱에 들어가는 값은 사용자가 꺼내 볼 수 있으므로 공개를 전제로 한 키만 넣는다.
