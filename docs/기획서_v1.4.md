## 1. 프로젝트 개요

### 1.1 한 줄 정의

물을 마실 때마다 내 화분에 물을 주고, 그 화분을 꾸미며 키우는 수분 섭취 습관 앱.

### 1.2 문제 정의

기존 물마시기 앱의 공통 문제는 **"기록은 되는데 계속 열지 않는다"** 는 것이다. 물 마시기는 보상이 즉각적이지 않고 체감 변화가 없어서, 단순 기록형 앱은 대부분 설치 후 3~7일 내에 이탈한다.

### 1.3 해결 방식

기록 행위 자체에 **즉각적인 시각 보상**을 붙인다.

- 물을 마신다 → 버튼을 누른다 → **화분에 물이 부어지고 식물이 자라는 애니메이션**이 재생된다
- 하루 목표를 채우면 → **꽃이 핀다**
- 꽃이 핀 화분은 → **내 정원에 보관되고, 꾸미기 아이템으로 교환할 수 있다**

즉 "물을 마시는 것"이 아니라 **"내 화분을 키우고 꾸미는 것"** 이 사용자가 앱을 여는 이유가 되도록 설계한다. 물 기록은 그 수단이 된다.

### 1.4 타겟 사용자

| 구분 | 내용 |
|---|---|
| 1차 타겟 | 20~30대 여성. 건강 관리에 관심 있고, 꾸미기·수집 요소가 있는 앱에 호감이 높은 층 |
| 2차 타겟 | 사무직 직장인 전반. 앉아서 일하다 물 마시는 것을 잊는 사용자 |
| 사용 맥락 | 하루 5~10회, 한 번에 3~10초. **짧고 잦은 사용**이 전제 — 앱 실행부터 기록 완료까지 2탭 이내여야 함 |

### 1.5 차별점

| 기존 물마시기 앱 | 본 앱 |
|---|---|
| 물컵 게이지가 차오르는 수준의 피드백 | 식물이 실제로 자라고 꽃이 피는 성장 서사 |
| 꾸미기 요소 없음 / 캐릭터 스킨 정도 | 눈·표정·데코를 자유 배치하는 나만의 화분 |
| 기록 누적 = 숫자 | 기록 누적 = 정원에 쌓이는 화분 |

### 1.6 성공 지표 (KPI)

| 지표 | 목표 | 측정 방법 |
|---|---|---|
| D1 리텐션 | 50% 이상 | Firebase Analytics |
| D7 리텐션 | 25% 이상 | Firebase Analytics |
| 일 평균 기록 횟수 | 4회 이상 | `intake_logged` 이벤트 |
| 꾸미기 화면 진입률 | 설치 후 3일 내 60% 이상 | `screen_view(decorate)` |
| 일일 목표 달성률 | 활성 사용자 중 35% 이상 | `daily_goal_achieved` 이벤트 |

> D7 리텐션 25%가 이 프로젝트의 **핵심 검증 지표**다. 이 수치가 나오지 않으면 수익화(11장)를 진행하지 않고 리텐션 개선에 집중한다.

| 순위 | 범위 | 포함 화면 / 기능 |
|---|---|---|

| 분석/크래시 | Firebase Analytics, Crashlytics | |
| CI/CD | GitHub Actions + Fastlane | 자동 빌드·배포 |
| 아키텍처 | Feature-first + 3계층 (data / domain / presentation) | 화면 단위 폴더 분리로 확장성 확보 |
| 다국어 | **flutter_localizations + intl (ARB)** | 문구 외부화를 처음부터 적용해 영어 추가 시 코드 수정을 최소화. 1.0은 한국어만 제공 (3.2) |

### 3.1 백엔드 정책 — MVP는 서버 없음

**출시 1.0은 서버를 구축하지 않는다.** 전 기능이 단말 로컬 DB만으로 동작한다.

| 근거 | 내용 |
|---|---|
| 데이터 특성 | 개인 음수 기록뿐. 다른 사용자와 공유되는 데이터가 없음 |
| 절감 효과 | 서버·인증·API 개발 제외 시 개발 기간 약 3~4주 단축, 운영비 0원 |
| 확장 경로 | 소셜 연동·기기 간 백업이 필요해지는 시점(P3)에 **Supabase** 도입. 사내 표준 준수가 필요하면 Kotlin + Spring Boot |

> **트레이드오프 (반드시 인지할 것)**: 서버가 없으면 **기기를 바꾸거나 앱을 삭제하면 데이터가 전부 사라진다.** 이는 사용자 불만의 직접 원인이 되므로, MVP에서는 최소한 **로컬 백업 파일 내보내기/가져오기 기능(설정 화면)** 을 P1으로 함께 제공한다.

### 3.2 다국어(i18n) 대응 원칙

출시 1.0은 **한국어만 지원**하지만, 이후 영어 추가를 위해 **구조는 처음부터 다국어 기반으로 만든다.** 번역 자체는 후순위이고, 번역할 수 있는 구조만 지금 확보한다.

| 원칙 | 내용 |
|---|---|
| 문자열 외부화 | 사용자에게 보이는 모든 문구는 ARB 파일(`app_ko.arb`)에서 불러온다. 코드·위젯에 한글 문자열을 직접 쓰지 않는다 |
| 문장 단위 관리 | 변수가 들어가는 문장은 조각으로 이어 붙이지 않고 하나의 메시지로 관리한다 (예: `오늘 {count}잔 마셨어요`). 어순·복수형은 ICU 메시지 문법으로 처리한다 |
| 에셋에 글자 금지 | 컵 아이콘, 꾸미기 아이템, Rive 에셋에 텍스트를 넣지 않는다 (언어별 재제작 방지) |
| 레이아웃 여유 | 버튼·탭·카드는 긴 문구에서도 줄바꿈이나 잘림이 생기지 않게 설계한다. 고정 폭 사용을 최소화한다 |
| 단위 | 저장은 ml·kg로 고정한다 (5.2, 7장). 표시 단위(oz, lb) 변환은 표시 계층에서만 처리하며, 해외 출시 시 도입한다 |
| 날짜·숫자 형식 | 날짜·시간·숫자 표기는 로케일 기준 포맷터(`intl`)를 사용한다 |
| 법적 문구 | 의학 고지, 이용약관, 개인정보처리방침은 번역이 아니라 지역별 검토 대상이다 (13장 #5, #7) |

> **1.0 범위**: 한국어 ARB 1종만 작성한다. 영어 추가는 ARB 파일 추가 + 영어용 폰트 확정 + 법적 문구 검토 + 스토어·알림 문구 준비로 진행한다.

## 4. 화면 구성 및 네비게이션

### 4.1 화면 목록

### 4.2 네비게이션 플로우

```
[앱 실행]
    │
    ├─ 온보딩 완료 여부 확인 (로컬 저장값)
    │
    ├─ 미완료 ──> S1 온보딩 ──(저장)──> S2 메인
    │
    └─ 완료 ────────────────────────> S2 메인
                                        │
                    ┌───────────────────┼───────────────────┐
                    │                   │                   │
              [통계 버튼]         [화분 탭/꾸미기]      [톱니바퀴]
                    │                   │                   │
                 S4 통계            S3 꾸미기            S5 설정
                    │                   │                   │
                 (뒤로)         (저장/취소 → S2)      (뒤로) │
                    │                   │                   │
                    └───────────────────┴───────────────────┘
                                        │
                                    S2 메인
```

- S2는 **항상 스택 최하단**에 존재한다. S3/S4/S5는 push, 뒤로가기 시 S2로 복귀.
- S3 꾸미기 화면은 **즉시 적용 방식이므로 뒤로가기 시 확인 다이얼로그를 띄우지 않는다.** 복구는 화면 내 되돌리기(↺) 버튼으로 처리한다 (6장 S3 참조).
- 알림 탭으로 앱 진입 시 → S2로 직행하며, **자동으로 물 기록되지 않는다** (오기록 방지).

## 5. 핵심 로직 정의

이 장은 화면 명세보다 우선한다. 여기서 정의한 규칙이 여러 화면에 공통 적용된다.

### 5.1 일일 목표 음수량 산정식

온보딩에서 사용자가 직접 입력하되, **입력값 기반 권장치를 먼저 제안**하고 수정 가능하게 한다.

```
기본량   = 체중(kg) × 33ml
성별보정 = 남성 1.00 / 여성 0.95 / 선택안함 0.97
연령보정 = 만 30세 이하 1.00 / 31~55세 0.95 / 56세 이상 0.90

권장량 = 기본량 × 성별보정 × 연령보정
       → 50ml 단위 반올림
       → 최소 1,000ml / 최대 3,500ml 범위로 제한(clamp)
```

**계산 예시**

| 입력 | 계산 | 권장량 |
|---|---|---|
| 여성 / 28세 / 55kg | 55×33×0.95×1.00 = 1,724 | **1,700ml** |
| 남성 / 35세 / 78kg | 78×33×1.00×0.95 = 2,445 | **2,450ml** |
| 여성 / 60세 / 48kg | 48×33×0.95×0.90 = 1,354 | **1,350ml** |

**구현 규칙**

- 사용자가 직접 수정한 값이 있으면 그 값을 우선한다 (`is_goal_custom = true`).
- 사용자가 수정하지 않은 상태에서 프로필(체중 등)을 변경하면 권장량을 **재계산하여 자동 반영**한다.
- 직접 입력 시 허용 범위는 **500ml ~ 4,000ml**. 범위 초과 입력은 저장을 막고 안내 문구를 표시한다.

> **[중요 · 안전 및 법적 고지]**
> 이 산정식은 일반적인 참고 기준이며 **의학적 조언이 아니다.** 단시간 과다 음수는 저나트륨혈증 등 실제 건강 위험을 유발할 수 있으므로 다음을 반드시 구현한다.
> 1. 목표량 상한을 4,000ml로 하드 제한한다.
> 2. 온보딩 목표 설정 화면과 설정 화면에 고지 문구를 상시 노출한다.
>    *"본 앱의 권장 음수량은 일반적인 참고 정보이며 의학적 조언이 아닙니다. 신장 질환·심부전 등 질환이 있거나 임신 중인 경우 반드시 의료 전문가와 상담하세요."*
> 3. 1일 누적 기록이 4,000ml를 초과하면 축하 연출 대신 중립적인 안내를 표시한다. **과다 섭취를 성취로 연출하지 않는다.**

### 5.2 물 기록 단위 — 컵 선택 방식

**원칙: 사용자는 "컵"으로 고르고, 데이터는 항상 "ml"로 저장한다.**
컵은 ml 프리셋의 겉모습일 뿐이다. 통계, 목표 달성 판정, 일일 상한(5.6.4), 반복 기록 확인(5.6.2)은 모두 기존대로 **ml와 기록 건수 기준**으로 동작한다. 컵 종류가 달라도 **기록 1건 = 1잔**이다.

| 컵 | 기본 용량 | 용량 수정 | 비고 |
|---|---|---|---|
| 종이컵 | 200ml | O | **신규 설치 시 초기 기본 컵** |
| 머그컵 | 300ml | O | |
| 텀블러 | 500ml | O | 제품별 편차가 커서 용량 수정이 사실상 필수 |
| 기타 | 350ml | O | 위 3종에 없는 컵·물병. 내 컵 용량을 직접 지정 |

- 용량 허용 범위는 **10 ~ 2,000ml, 10ml 단위**. 화면의 −/+ 버튼은 **50ml 단위**로 증감하고(범위를 벗어나면 경계값으로 고정), 용량 숫자를 탭하면 직접 입력할 수 있다.
- **기본 컵** = 메인 버튼을 짧게 탭했을 때 기록되는 컵. 온보딩에서는 컵을 묻지 않는다(입력 마찰 최소화). 변경은 기록 시트 또는 S5-1에서 한다.
- 컵 용량을 수정해도 **이미 저장된 과거 기록은 바뀌지 않는다.** (`intake_log.amount_ml`은 기록 시점의 값)

**동작 규칙**

- 메인 물 마시기 버튼에는 **컵 아이콘 + "{컵 이름} {용량}ml 마시기"** 를 한 줄로 표시한다 (예: 머그컵 300ml 마시기). 동작 문구와 컵 정보를 한 줄에 합쳐 버튼을 간결하게 유지한다.
- 메인 버튼 **짧게 탭** → 기본 컵 용량 즉시 기록
- 메인 버튼 **길게 누름(500ms)** → 기록 시트 표시
  - 컵 4종 카드(아이콘·이름·용량) + 잔 수 스테퍼(1~10) + "용량 수정" 링크(→ S5-1)
  - 컵 카드를 탭하면 선택 상태가 바뀌고 **즉시 기본 컵으로 저장**된다 (시트를 닫아도 유지, 다음 짧게 탭부터 적용)
  - `기타`를 선택하면 용량을 직접 입력한다 (10~2,000ml)
  - 확정 버튼 문구는 `{총 ml}ml 기록하기`, 그 아래에 `{컵 용량}ml N건으로 나뉘어 저장돼요`를 표시한다
- 기록 직후 **5초간 "되돌리기" 스낵바 노출** (오탭 대응, 필수)

**묶음 기록 (필수)**

기록 시트에서 컵을 고른 뒤 `− 3 +` 스테퍼로 잔 수를 지정해 **한 번에 기록**할 수 있다. 저장 시 `900ml` 1건이 아니라 **`300ml × 3건`으로 분리 저장**한다 (통계의 "오늘 N잔" 표시와 시간대별 그래프 정합성 유지).

> 이 기능이 없으면 "깜빡했다가 몰아서 기록"하는 사용자가 버튼을 연타할 수밖에 없다. **연타를 막기 전에 연타하지 않아도 되는 경로를 먼저 제공한다.** 5.6의 전제 조건이다.

> **컵 방식을 택한 이유와 한계**: 컵 이름이 숫자보다 직관적이고 "내 컵을 고른다"는 개인화 요소가 되지만, 컵 크기는 사람마다 다르다. 그래서 컵 평균값을 쓰지 않고 **사용자가 용량을 직접 수정**할 수 있게 하며, 저장은 ml로 고정해 진행률의 정확성을 지킨다.

### 5.3 화분 성장 단계

당일 달성률(`오늘 누적 음수량 ÷ 일일 목표량`) 기준 5단계.

| 단계 | 달성률 | 화분 상태 | 전환 연출 |
|---|---|---|---|
| 1 | 0 ~ 20% | 흙 + 씨앗 | — |
| 2 | 21 ~ 40% | 새싹 (떡잎 2장) | 새싹이 솟아오름 |
| 3 | 41 ~ 60% | 줄기 + 잎 4장 | 줄기가 자람 |
| 4 | 61 ~ 99% | 꽃봉오리 | 봉오리 맺힘 |
| 5 | **100% 이상** | **개화** | 꽃이 피며 축하 연출 + 햅틱 |

**동작 규칙**

- 물 기록 시 **항상 물 붓기 애니메이션(약 1.2초)** 재생. 단계 상승이 동시에 발생하면 물 붓기 → 성장 연출 순으로 이어서 재생한다.
- 기록을 되돌리기(취소)하면 단계가 **역행할 수 있다.** 이 경우 성장 애니메이션은 재생하지 않고 상태만 조용히 되돌린다.
- 100% 달성 축하 연출은 **하루 1회만** 재생한다 (`daily_summary.celebrated` 플래그).
- 당일 누적이 **4,000ml를 초과**하면 (달성률과 무관하게) 5.1의 안전 규칙에 따라 축하 연출 없이 중립 안내를 표시한다.

### 5.4 자정 리셋 및 스트릭

**리셋 규칙**

- 하루의 경계는 **로컬 시간 기준 00:00**.
- 앱을 켠 시점에 마지막 조회 날짜와 오늘 날짜를 비교하여, 다르면 새 날짜의 `daily_summary`를 생성하고 화분을 1단계로 초기화한다.
- **[구현 주의]** 백그라운드 상태로 자정을 넘긴 뒤 포그라운드 복귀하는 케이스를 반드시 처리한다. `AppLifecycleState.resumed` 시점에 날짜를 재검증한다.
- 해외 이동으로 시간대가 바뀌어도 기록은 **저장 시점의 로컬 날짜**에 귀속시킨다(UTC 변환 후 표시 시 재변환하지 않는다). 서머타임 구간에서도 날짜 경계가 중복·누락되지 않아야 한다.

**스트릭(연속 달성일)**

매일 화분이 초기화되면 누적 성취감이 사라진다. 이를 보완하는 핵심 장치다.

| 규칙 | 내용 |
|---|---|
| 증가 | 하루 목표 100% 달성 시 `current_streak + 1` |
| 유지 | 자정 넘김 시점에 전날 목표 미달성이면 `current_streak = 0` |
| 최고 기록 | `best_streak`은 감소하지 않음 |
| 표시 | 메인 화면 상단에 `🔥 N일 연속` 형태로 노출 |

> **P3 확장 제안 — 정원(Garden)**: 목표를 달성한 날의 화분을 "정원"에 보관하여 캘린더 형태로 되돌아볼 수 있게 한다. 매일 리셋되는 구조의 허전함을 메우는 가장 효과적인 장치이며, 리텐션 개선이 필요할 경우 1순위로 추가할 기능이다.

### 5.5 알림 스케줄링 규칙

| 항목 | 기본값 | 설정 가능 |
|---|---|---|
| 알림 사용 | OFF (사용자가 켜야 동작) | O |
| 활동 시간대 | 08:00 ~ 22:00 | O |
| 알림 간격 | 2시간 | O (1 / 2 / 3시간) |
| 목표 달성 후 | 당일 잔여 알림 **전부 취소** | 고정 |

**동작 규칙**

- 물을 기록할 때마다 **다음 알림 시각을 재계산**한다. 방금 물을 마셨는데 10분 뒤 알림이 오는 상황을 방지한다.
- 활동 시간대 밖에는 알림을 발송하지 않는다.
- 알림 문구는 3~5종을 랜덤 노출한다. 예: *"화분이 목말라 해요 🌱"*, *"오늘 목표까지 700ml 남았어요"*
- **권한 요청 타이밍**: 온보딩 직후가 아니라, 사용자가 **설정에서 알림을 직접 켤 때** 요청한다. 맥락 없이 요청하면 거부율이 크게 올라가고, iOS는 한 번 거부되면 앱 내에서 재요청할 수 없다.
- 권한이 거부된 상태에서 알림 토글을 켜면 → OS 설정 화면으로 이동하는 안내 다이얼로그를 표시한다.

### 5.6 연타 및 어뷰징 방지 정책

물마시기 버튼은 연타가 구조적으로 발생하는 UI다. 다만 **"빠르게 여러 번 누르는 행위"에는 성격이 전혀 다른 세 가지가 섞여 있으므로**, 하나의 규칙으로 일괄 차단하면 정상 사용자가 피해를 본다. 유형별로 다르게 처리한다.

| 유형 | 상황 | 의도 | 처리 방향 |
|---|---|---|---|
| **A. 오탭** | 1초 내 중복 탭. 손가락이 미끄러지거나 반응이 없어 다시 누름 | 없음 (사고) | **완전 차단** |
| **B. 몰아서 기록** | 오후에 접속해 "아침·점심에 마신 3잔"을 한꺼번에 기록 | 정당함 | **차단 금지.** 묶음 기록으로 유도 |
| **C. 어뷰징** | 아이템 해금을 노려 목표를 연타로 채움 | 보상 획득 | **차단보다 이득 제거** |

#### 5.6.1 A. 오탭 차단 — 애니메이션 쿨다운

| 규칙 | 값 |
|---|---|
| 쿨다운 시간 | **1.2초** (물 붓기 애니메이션 길이와 동일) |
| 쿨다운 중 버튼 상태 | 비활성화 + 투명도 50% + 터치 무시 |
| 쿨다운 중 입력 처리 | **무시한다. 큐에 쌓지 않는다** |

- 애니메이션이 곧 쿨다운이 되므로 별도의 대기 UI가 필요 없다. 사용자는 "지금은 누를 수 없다"를 시각적으로 인지한다.
- **[변경 사항]** 초기 명세는 "애니메이션 중 추가 탭도 기록에 반영"이었으나, 이를 **무시로 변경**한다. 오탭이 조용히 기록되면 사용자가 알아차리지 못한다.
- 쿨다운 중 탭이 감지되면 버튼을 짧게 흔드는 피드백(shake 0.2초)만 준다. 토스트는 띄우지 않는다 (연타 시 토스트가 도배됨).

#### 5.6.2 B. 정당한 반복 기록 — 마찰만 준다

차단하지 않되, 무의식적 연타에는 한 번 멈춰 세운다.

| 조건 | 처리 |
|---|---|
| 최근 **60초 내 3회** 기록 완료 후, 4회째 시도 | 확인 시트 표시 |

**확인 시트 내용**

```
방금 1분 동안 3잔(600ml)을 기록했어요.
정말 더 마셨나요?

[ 여러 잔을 한 번에 기록하기 ]   ← 묶음 기록 시트로 이동
[ 네, 1잔 더 기록 ]
[ 취소 ]
```

- 확인 후에는 60초 카운터를 초기화하고 정상 기록한다. **같은 세션에서 반복적으로 묻지 않는다.**
- 묶음 기록으로 저장된 건은 이 카운터에 포함하지 않는다 (정당한 경로를 쓴 사용자를 벌주지 않는다).
- 되돌리기로 취소된 기록도 카운터에서 제외한다.
- **쿨다운 타이머와 60초 카운터는 메모리 상태로만 관리한다(DB 저장 불필요).** 앱을 재시작하면 초기화되지만, 어뷰징의 실익이 이미 5.6.3에서 제거되어 있으므로 우회를 방어할 필요가 없다. 이 두 장치의 목적은 **차단이 아니라 무의식적 연타를 인지시키는 것**이다. 하드 리밋(5.6.4)만 DB 기반으로 관리한다.

#### 5.6.3 C. 어뷰징 — 이득을 제거하는 것이 본질

**보상을 "총량"이 아니라 "일수"에 연동하면 연타의 이득이 사라진다.** 이미 6장 S3의 해금 조건이 이 구조로 설계되어 있으며, 아래 원칙을 명시적으로 고정한다.

| 원칙 | 내용 |
|---|---|
| **시간은 조작 불가** | 아이템 해금 조건은 전부 `스트릭 N일` 또는 `누적 달성 N일`. 하루에 몇 번 누르든 **그날은 1일로만 카운트**된다. 30일 아이템은 실제로 30일이 지나야 열린다 |
| **총량 기반 보상 금지** | "누적 100L 달성" 같은 총량 조건은 **도입하지 않는다.** 연타로 즉시 달성 가능해 어뷰징에 직접 노출된다 |
| **하루 1회 상한** | 스트릭 증가, 축하 연출, 달성 카운트는 모두 **하루 1회**로 제한 (5.3, 5.4에 이미 반영) |

즉 연타로 하루 목표를 채워도 얻는 것은 **하루치 스트릭 하나뿐**이며, 다음 아이템까지는 여전히 며칠을 기다려야 한다. 어뷰징의 기대 이득이 거의 없으므로 **강한 차단 로직이 불필요하다.**

#### 5.6.4 하루 기록 상한 (하드 리밋)

건강 안전(5.1)과 어뷰징 방지를 동시에 만족시키는 최종 방어선이다.

| 항목 | 상한 | 초과 시 처리 |
|---|---|---|
| 일일 누적 총량 | **4,000ml** | 기록 차단 + 안내: *"오늘은 충분히 마셨어요. 과도한 수분 섭취는 오히려 몸에 부담이 될 수 있어요."* |
| 일일 기록 횟수 | **30회** | 기록 차단 + 안내: *"오늘 기록은 여기까지예요. 내일 다시 만나요 🌱"* |

- 정상 사용자의 최대 사용량(목표 2,000ml를 100ml씩 = 20회)을 크게 상회하는 값이므로 오탐 위험이 없다.
- 횟수 상한은 100ml 소량 연타로 총량 상한을 우회하는 것을 막는다.
- 두 상한 중 **하나라도** 도달하면 당일 기록 버튼을 비활성화한다.

#### 5.6.5 이상 패턴 코칭 (차단 아님)

| 조건 | 처리 |
|---|---|
| 일일 목표 100%를 **10분 이내**에 달성 | 축하 연출은 정상 재생. 이어서 안내: *"한 번에 많은 양을 기록했어요. 물은 조금씩 나눠 마시는 게 몸에 더 좋아요 🌱"* |

- **스트릭은 정상 인정한다.** 몰아서 기록한 정당한 사용자(유형 B)를 벌주지 않기 위함이다.
- 건강 측면에서도 맞는 조언이므로 어뷰징 억제와 사용자 이익이 일치한다.

> **P3 주의사항**: 소셜 연동으로 친구 간 비교·랭킹이 도입되면 어뷰징 유인이 급격히 커진다. 그 시점에는 클라이언트 규칙만으로 부족하므로 **서버 측 검증(기록 간격·패턴 분석)** 을 함께 설계해야 한다. MVP에는 불필요하다.

## 6. 화면별 상세 기능정의

### S1. 온보딩 (프로필 입력) — P0

**목적**: 일일 목표량 산정에 필요한 최소 정보를 받고, 첫 화분을 배정한다.

**진입/이탈**: 최초 실행 1회. 완료 시 `onboarding_completed = true` 저장 후 S2로 이동. **뒤로가기로 건너뛸 수 없다.**

**구성 — 3단계 스텝 형식** (한 화면에 6개 입력을 몰아넣으면 이탈률이 급증하므로 분할한다)

| 스텝 | 입력 항목 | 필수 |
|---|---|---|
| 1 | 별명 | 필수 |
| 2 | 성별, 나이, 키, 몸무게 | 성별/나이/몸무게 필수, 키 선택 |
| 3 | 일일 목표 음수량 (권장치 자동 제시 + 수정) | 필수 |

**입력값 정의 및 유효성**

| 항목 | 타입 | 범위 / 형식 | 오류 메시지 |
|---|---|---|---|
| 별명 | String | 1~10자, 공백만 입력 불가, 이모지 허용 | "별명을 1~10자로 입력해 주세요" |
| 성별 | Enum | 남성 / 여성 / 선택 안 함 | — |
| 나이 | Int | 14 ~ 100 | "만 14세 이상만 이용할 수 있어요" |
| 키 | Int | 100 ~ 250 (cm), **선택 입력** | "키를 확인해 주세요" |
| 몸무게 | Int | 30 ~ 200 (kg) | "몸무게를 확인해 주세요" |
| 일일 목표량 | Int | 500 ~ 4,000 (ml), 10ml 단위 | "500~4,000ml 사이로 입력해 주세요" |

> **키는 선택 입력으로 둔다.** 5.1 산정식에 키가 쓰이지 않으므로 필수로 받을 근거가 없다. 개인정보 최소 수집 원칙에도 부합한다. (향후 BMI 기반 산정으로 고도화할 여지는 남겨 컬럼은 유지)
>
> **만 14세 미만 차단**: 국내 개인정보보호법상 만 14세 미만은 법정대리인 동의가 필요하므로, 나이 하한을 14세로 설정한다. `[결정필요]` 해외 출시 시 GDPR(16세) 기준 별도 검토.

**동작 명세**

1. 스텝 2 완료 시 5.1 산정식으로 권장량을 계산해 스텝 3에 **미리 채워** 보여준다.
2. 스텝 3에는 *"체중을 기준으로 계산한 권장량이에요. 원하는 값으로 바꿀 수 있어요."* 안내와 5.1의 의학 고지 문구를 함께 노출한다.
3. 사용자가 값을 수정하면 `is_goal_custom = true`로 저장한다.
4. 완료 버튼 → `user_profile` 저장 → 첫 화분(기본 스킨) 생성 → S2로 이동.

**예외 처리**

- 각 스텝의 필수값 미입력 시 다음 버튼 비활성화.
- 입력 중 앱이 강제 종료되면 온보딩은 처음부터 다시 시작한다 (중간 저장 없음, MVP 기준).

**AC (인수조건)**

- [ ] 필수값을 모두 채우기 전에는 다음 단계로 진행할 수 없다
- [ ] 여성/28세/55kg 입력 시 목표량이 **1,700ml**로 자동 제시된다
- [ ] 목표량을 4,001ml로 입력하면 저장이 차단되고 오류 문구가 표시된다
- [ ] 나이를 13으로 입력하면 저장이 차단된다
- [ ] 온보딩 완료 후 앱을 재실행하면 S1이 아닌 S2로 진입한다
- [ ] 의학 고지 문구가 목표 설정 단계에 표시된다

### S2. 메인 화면 — P0

**목적**: 앱의 홈. 오늘의 진행 상황을 한눈에 보여주고, 최소 조작으로 물을 기록한다.

**레이아웃 구성**

```
┌─────────────────────────────────────┐
│  물마시GO         🔥 12일 연속 [설정]│  ← 상단 바 (앱 이름은 가칭)
├─────────────────────────────────────┤
│  오늘 마신 물: 900ml / 목표 2,000ml  │  ← 진행 카드
│  ▓▓▓▓▓▓▓▓░░░░░░░░░░░░               │
├─────────────────────────────────────┤
│                                     │
│            🌿 화분 영역             │  ← 탭하면 S3 꾸미기
│         (Rive 애니메이션)           │
│            성장 단계 3              │
│                                     │
├─────────────────────────────────────┤
│    ┌─────────────────────────┐      │
│    │ [컵] 머그컵 300ml 마시기 │      │  ← 짧게 탭 / 길게 누름
│    └─────────────────────────┘      │
│    오늘 5잔 마셨어요                 │
│                                     │
│     (식물 꾸미기)     (통계)         │  ← 원형 버튼
└─────────────────────────────────────┘
```

**구성 요소 상세**

| 요소 | 내용 | 동작 |
|---|---|---|
| 앱 이름 | 상단 좌측 | 표시 전용 (이름 확정 전 가칭, 13장 #1) |
| 스트릭 배지 | `🔥 N일 연속` | 0일이면 미표시 |
| 설정 톱니바퀴 | 상단 우측 | → S5 |
| 진행 카드 | `오늘 마신 물: 현재ml / 목표 ml` + 진행바 | 기록 시 0.4초 애니메이션으로 증가. 퍼센트 숫자는 표시하지 않고 진행바와 화분 성장 단계로 표현 |
| 화분 영역 | Rive 애니메이션, 꾸미기 아이템 오버레이, 하단 `성장 단계 N` 라벨 | 탭 → S3 |
| 물 마시기 버튼 | 화면 하단 중앙, 최소 터치 영역 64dp. 컵 아이콘 + `{컵 이름} {용량}ml 마시기` (한 줄) | 짧게 탭 / 길게 누름 (5.2) |
| 하단 요약 | `오늘 N잔 마셨어요 · 짧게 탭 {용량}ml, 길게 누르면 컵 선택` | 기록 수 기준 |
| 식물 꾸미기 버튼 | 원형 버튼 + 라벨 | → S3 |
| 통계 버튼 | 원형 버튼 + 라벨 | → S4 |

**동작 명세**

1. **짧게 탭** → 기본 컵 용량(5.2) 즉시 기록 → 물 붓기 애니메이션(1.2초) + 햅틱 → 진행바 증가 → 5초간 "되돌리기" 스낵바
2. **길게 누름(500ms)** → 하단 시트: 컵 선택(종이컵/머그컵/텀블러/기타) + 묶음 스테퍼 + 용량 수정 링크 (5.2)
3. 기록으로 성장 단계가 올라가면 물 붓기 연출 뒤 성장 연출을 이어 재생
4. 100% 최초 달성 시 개화 + 축하 연출 + 스트릭 +1 (하루 1회)
5. **연타 처리 (5.6 참조)** — 기록 직후 **1.2초간 버튼을 비활성화**하고, 이 구간의 탭은 **무시한다**(큐잉하지 않음). 쿨다운 중 탭 시 버튼 shake 피드백만 제공
6. **반복 기록 확인** — 최근 60초 내 3회 기록 후 4회째 시도 시 확인 시트 표시 (5.6.2)
7. **상한 도달** — 일일 4,000ml 또는 30회 도달 시 버튼을 당일 비활성화하고 안내 문구 표시 (5.6.4)

**예외 처리**

| 상황 | 처리 |
|---|---|
| 애니메이션 재생 중 재탭 | **기록되지 않음.** 버튼 비활성 + shake 피드백 (5.6.1) |
| 60초 내 4회째 기록 시도 | 확인 시트 → 승인 시 기록, 취소 시 무기록 (5.6.2) |
| 일일 상한 도달 후 탭 | 기록 차단 + 안내 문구. 버튼은 자정까지 비활성 (5.6.4) |
| 되돌리기 후 즉시 재기록 | 정상 처리. 쿨다운·60초 카운터 모두 재계산 |
| 백그라운드에서 자정 경과 후 복귀 | 날짜 재검증 → 화분 초기화, 스트릭 갱신 (5.4) |
| DB 쓰기 실패 | 토스트 "기록에 실패했어요. 다시 시도해 주세요" + 로컬 상태 롤백 |

**AC**

- [ ] 버튼 1탭으로 기본 컵 용량(초기값 종이컵 200ml)이 기록되고 진행 표시가 즉시 갱신된다
- [ ] 기록 직후 5초간 되돌리기가 노출되고, 누르면 해당 기록만 취소된다
- [ ] 달성률 41%가 되는 순간 화분이 3단계(줄기+잎)로 전환된다
- [ ] 목표 100% 달성 시 개화 연출과 축하가 **1회만** 재생된다
- [ ] 앱을 백그라운드에 둔 채 자정을 넘기고 복귀하면 화분이 1단계로 초기화된다
- [ ] 누적 4,000ml 초과 시 축하 연출 대신 중립 안내가 표시된다
- [ ] 꾸미기에서 저장한 아이템이 메인 화면 화분에 동일하게 표시된다
- [ ] **버튼을 1초 안에 5회 연타해도 기록은 1건만 생성된다**
- [ ] 쿨다운(1.2초) 중에는 버튼이 비활성 상태로 보이고, 탭 시 shake 피드백만 발생한다
- [ ] 60초 내 3회 기록 후 4회째 탭 시 확인 시트가 뜨고, 취소하면 기록되지 않는다
- [ ] 확인 시트에서 "여러 잔을 한 번에 기록하기"를 누르면 묶음 기록 시트로 이동한다
- [ ] 묶음 기록으로 200ml×3을 저장하면 `intake_log`에 3건이 생성되고 "오늘 3잔"으로 집계된다
- [ ] 묶음 기록은 60초 반복 카운터에 포함되지 않는다
- [ ] 일일 누적 4,000ml 또는 30회 도달 시 버튼이 비활성화되고 자정 이후 다시 활성화된다
- [ ] 목표 100%를 10분 이내에 달성하면 축하 후 분할 섭취 안내가 표시되고, 스트릭은 정상 증가한다

*컵 선택*

- [ ] 메인 버튼에 기본 컵의 아이콘·이름·용량이 한 줄로 표시된다 (예: 머그컵 300ml 마시기)
- [ ] 기본 컵을 머그컵(300ml)으로 바꾸면 짧게 탭 시 300ml가 기록된다
- [ ] 기록 시트에서 컵 카드를 탭하면 선택 상태가 바뀌고, 앱을 재실행해도 기본 컵으로 유지된다
- [ ] 기록 시트에서 머그컵 × 3잔을 선택하면 "머그컵 300ml × 3잔 = 900ml"와 "300ml 3건으로 나뉘어 저장돼요"가 표시되고, `intake_log`에 300ml 3건이 생성된다
- [ ] 컵 용량을 수정해도 이미 저장된 과거 기록의 `amount_ml`은 바뀌지 않는다
- [ ] 컵 종류와 무관하게 "오늘 N잔"은 기록 건수로 집계된다
- [ ] 컵 종류가 달라도 일일 4,000ml·30회 상한은 ml와 건수 기준으로 동일하게 적용된다

### S3. 꾸미기 화면 — P1

**목적**: 화분을 개인화한다. 앱을 다시 열게 만드는 핵심 재미 요소.

**진입/이탈**: S2 화분 탭 → S3. 뒤로가기로 S2 복귀 (**저장/취소 버튼 없음** — 아래 "적용 방식" 참조).

**레이아웃**

```
┌─────────────────────────────────────┐
│  [←]       식물 꾸미기        [↺]    │  ← 우상단 되돌리기 (저장/취소 버튼 없음)
├─────────────────────────────────────┤
│                                     │
│         🌿 화분 미리보기            │  ← 선택 즉시 반영 (조작 불가, 보기 전용)
│                                     │
├─────────────────────────────────────┤
│ [화분][눈][코][입][볼][머리][배경]  │  ← 카테고리 탭 (가로 스크롤)
├─────────────────────────────────────┤
│  🚫  ⬜  ⬜  ⬜                     │  ← 🚫 = "없음" (해제)
│  ⬜  ⬜  🔒  🔒                     │  ← 아이템 그리드 (🔒 = 미해금)
│  🔒  🔒  🔒  🔒                     │
└─────────────────────────────────────┘
```

**적용 방식 — 즉시 적용 + 되돌리기 (저장 버튼 없음)**

아이템을 탭하면 **미리보기 반영과 저장이 동시에 일어난다.** 별도의 저장·적용·취소 버튼을 두지 않고, 우상단 **되돌리기(↺)** 버튼 하나로 복구를 처리한다.

| 검토안 | 구성 | 판정 |
|---|---|---|
| A. 즉시 적용 + 되돌리기 | 뒤로, 되돌리기 (버튼 2개) | **채택** |
| B. 적용 버튼 + 되돌리기 | 취소, 저장, 되돌리기 (버튼 3개) | 미채택 |

**A를 채택한 이유**

1. **되돌리기와 취소 버튼은 같은 문제(실수 복구)를 푸는 중복 장치다.** 되돌리기를 두는 순간 취소 버튼의 존재 이유가 사라진다.
2. **저장 버튼을 누르지 않고 이탈하는 사용자가 실제로 많다.** 꾸미기는 열중하다 뒤로가기를 누르기 쉬운 화면이라, B 방식은 작업 소실 또는 확인 팝업 중 하나를 반드시 발생시킨다.
3. 하루 5~10회 · 회당 3~10초 쓰는 앱이다. 저장 단계는 이 사용 맥락에서 순수한 마찰이다.
4. 꾸미기는 과업이 아니라 **놀이**다. 탭할 때마다 내 화분이 즉시 바뀌는 것이 재미 자체이며, 저장 버튼은 이를 "작업"으로 만든다.

**되돌리기(↺) 동작 정의**

| 항목 | 정의 |
|---|---|
| 방식 | **단계별 Undo (스택 기반).** 마지막 변경 1건씩 되돌린다 |
| 스택 생성 | S3 진입 시 초기화. 진입 시점 상태를 기준점으로 기록 |
| push 시점 | 아이템 교체 또는 `없음` 해제 시 `(category, 이전 item_id)` 를 push |
| 탭 동작 | pop → 해당 카테고리를 이전 값으로 복원 → 즉시 저장 |
| 최대 깊이 | 20단계 (초과 시 가장 오래된 항목 폐기) |
| 비활성 조건 | 스택이 비면 투명도 40%로 비활성. 진입 직후 상태 |
| 스택 폐기 | S3 이탈 시 폐기. 재진입 시 이전 스택은 복원하지 않는다 |

- **전체 원복 버튼은 두지 않는다.** 되돌리기를 계속 누르면 스택이 진입 시점까지만 쌓여 있으므로 **자연히 원래 상태에 도달**한다. 별도 버튼은 불필요한 중복이다.
- **다시 실행(Redo)은 넣지 않는다.** 되돌리기를 잘못 눌렀다면 그리드에서 다시 탭하면 되므로, 복잡도 대비 가치가 없다.
- 아이콘만으로는 의미 전달이 약하므로 아이콘 아래 작은 라벨 `되돌리기` 를 함께 표기한다.

**저장 처리**

- 매 탭마다 `user_decoration`에 write 한다. 7행 테이블이므로 비용은 무시 가능하다.
- 다만 빠른 연속 탭 시 write가 몰리지 않도록 **300ms 디바운스**를 적용하고, 화면 이탈 시 즉시 flush 한다.
- 첫 진입 1회에 한해 안내 토스트를 표시한다: *"고르면 바로 적용돼요"*

**조작 방식 — 탭 교체 방식 (자유 배치 없음)**

각 부위의 **위치·크기·각도는 전부 고정**이다. 사용자는 카테고리 탭에서 부위를 고르고, 하단 그리드에서 아이템을 탭하기만 한다. 해당 부위의 그림만 교체된다.

- **드래그·핀치·회전 없음.** 미리보기 영역은 보기 전용이며 제스처를 받지 않는다.
- 아이템 1탭 = 즉시 교체 + 미리보기 반영. 확인 단계 없음.
- 같은 카테고리의 다른 아이템을 탭하면 기존 것과 **교체**된다 (중복 착용 없음).

> **이 방식을 택한 이유**
> 1. 자유 배치는 눈이 화분 밖으로 나가거나 코가 뒤집힌 결과물을 만들기 쉽다. 고정 위치는 **어떤 조합을 골라도 항상 예쁘게 나온다.**
> 2. 하루 5~10회, 회당 3~10초 쓰는 앱이다. 손가락으로 위치를 맞추는 조작은 이 사용 맥락에 맞지 않는다.
> 3. 위치 데이터를 저장·복원할 필요가 없어 개발량이 크게 줄고, 기기 해상도별 좌표 어긋남 버그가 원천 제거된다.

**아이템 슬롯 구조**

| # | 카테고리 | 슬롯 | "없음" 허용 | 고정 위치 기준 |
|---|---|---|---|---|
| 1 | 배경 | 1 | 불가 (기본 배경 존재) | 화면 전체 |
| 2 | 화분(용기) | 1 | 불가 (기본 화분 존재) | 하단 중앙 |
| 3 | 눈 | 1 | 불가 | 화분 상단 중앙 |
| 4 | 코 | 1 | **허용** | 눈 아래 중앙 |
| 5 | 입 | 1 | 불가 | 코 아래 중앙 |
| 6 | 볼 | 1 | **허용** | 눈 바깥쪽 좌·우 (1개 아이템이 좌우 한 쌍) |
| 7 | 머리장식 | 1 | **허용** | 화분 상단 테두리 |

- 코·볼·머리장식은 그리드 첫 칸에 **`🚫 없음`** 옵션을 둔다. 없어도 자연스러운 부위이므로 해제할 수 있어야 한다.
- 눈·입은 캐릭터 정체성이라 해제를 허용하지 않는다. 대신 기본 아이템이 항상 장착되어 있다.
- **소품은 MVP에서 제외한다.** 소품은 본래 "화분 옆 자유 배치"가 전제인 카테고리라 고정 위치 방식과 맞지 않는다. 필요하면 P3에서 `화분 발치` 고정 슬롯 1개로 추가한다.

**렌더링 순서 (z_index)**

```
배경 → 화분(용기) → 식물(성장 단계) → 볼 → 입 → 코 → 눈 → 머리장식
  0        10             20          30    40    50    60      70
```

`z_index`는 `decoration_item` 마스터에 카테고리별 고정값으로 넣는다. 런타임 계산하지 않는다.

**고정 앵커 정의 — [중요 · 기술 결정]**

식물은 성장 5단계에 걸쳐 모양과 높이가 변한다. **얼굴 부위를 식물에 붙이면 단계마다 위치가 어긋나므로, 모든 얼굴 부위와 머리장식은 "식물"이 아니라 "화분(용기)"을 기준으로 배치한다.**

| 결정 | 내용 |
|---|---|
| 앵커 기준점 | 화분(용기) 이미지의 좌상단 (0,0) ~ 우하단 (1,1) 정규화 좌표 |
| 저장 위치 | `decoration_item` 마스터의 카테고리별 고정 앵커. **사용자 데이터로 저장하지 않는다** |
| 성장 단계 영향 | **없음.** 화분은 5단계 내내 크기·위치가 고정이고 식물만 위로 자란다 |

이 구조의 이점:

- 성장 단계별 앵커를 따로 관리할 필요가 없다 (Rive 상태 머신이 단순해짐)
- 5단계에서 꽃이 피어도 **머리장식이 꽃을 가리지 않는다** (머리장식은 화분 테두리에 위치)
- 화분이 얼굴을 가진 캐릭터가 되고 식물이 그 위로 자라는 형태 — 시각적으로도 가장 안정적

**아이템 에셋 규격**

- 카테고리별로 **동일한 캔버스 크기**로 제작한다 (예: 눈 카테고리는 전부 200×80px). 앵커에 그대로 얹으면 정렬이 맞아야 한다.
- 투명 배경 PNG(@1x/@2x/@3x) 또는 SVG.
- 개별 아이템마다 좌표를 따로 지정하는 일이 없어야 한다. **정렬은 에셋 제작 단계에서 끝낸다.**

**아이템 해금 조건 (MVP)**

**카테고리별 아이템 수량 (MVP 목표: 총 33종)**

| 카테고리 | 총 종수 | 기본 제공 | 해금 |
|---|---|---|---|
| 배경 | 3 | 1 | 2 |
| 화분(용기) | 4 | 1 | 3 |
| 눈 | 6 | 2 | 4 |
| 코 | 4 (+없음) | 2 | 2 |
| 입 | 6 | 2 | 4 |
| 볼 | 4 (+없음) | 1 | 3 |
| 머리장식 | 6 (+없음) | 1 | 5 |
| **합계** | **33** | **10** | **23** |

**해금 조건**

| 조건 유형 | 해금 시점 |
|---|---|
| 기본 제공 | 온보딩 완료 시 10종 즉시 지급 |
| 스트릭 달성 | **3 / 5 / 7 / 10 / 14 / 21 / 30일** 연속 달성 (7개 지점) |
| 누적 달성일 | 총 **5 / 10 / 20 / 30 / 50 / 70 / 100일** 달성 (7개 지점) |

- 해금 지점 14개에서 아이템 1~2종씩 지급하여 23종을 배분한다. 배분표는 디자인 확정 후 별도 시트로 관리한다.
- 초반 이탈 방지를 위해 **3일·5일 지점에 눈·입 등 체감이 큰 카테고리를 배치**한다. 배경·화분 같은 큰 변화는 중후반에 둔다.
- 해금 발생 시 메인 화면 복귀 시점에 축하 시트를 띄운다: *"3일 연속 달성! 새로운 눈이 열렸어요 👀"* → [꾸며보기] 버튼으로 S3 직행.

> **해금 조건은 전부 "일수" 기준이며, 총량·횟수 기반 조건은 도입하지 않는다.** (5.6.3) "누적 100L 달성" 같은 조건은 버튼 연타로 즉시 달성 가능해 어뷰징에 직접 노출된다. 일수 조건은 실제 시간이 흘러야 하므로 조작이 불가능하다. **향후 아이템을 추가할 때도 이 원칙을 반드시 유지할 것.**
>
> MVP는 **전 아이템 무료**로 출시한다. 유료 아이템 도입은 11장 참조.

**동작 명세**

1. 진입 시 현재 장착 상태를 로드하고, **현재 장착된 아이템은 그리드에서 선택 표시(테두리 강조)** 한다.
2. 진입 시 기본 활성 탭은 **`눈`** — 변화가 가장 잘 보이는 카테고리를 첫 화면에 둔다.
3. 카테고리 탭 전환 시 그리드만 교체된다. 미리보기는 유지된다.
4. 해금 아이템 탭 → 해당 슬롯 즉시 교체 → 미리보기 반영 + 즉시 저장 (+ 가벼운 햅틱) → Undo 스택 push → 되돌리기 버튼 활성화
5. `🚫 없음` 탭 → 해당 슬롯 해제 (코·볼·머리장식만). 이 또한 Undo 대상이다
6. 미해금 아이템 탭 → 교체하지 않고 해금 조건 안내 시트 표시 (예: *"7일 연속 달성 시 열려요"*). **Undo 스택에 쌓이지 않는다**
7. **되돌리기(↺) 탭** → 마지막 변경 1건 복원 + 즉시 저장. 되돌린 부위의 카테고리 탭으로 자동 전환하여 변화를 보여준다
8. **뒤로가기** → 확인 없이 즉시 S2 복귀. 이미 저장되어 있으므로 메인 화분에 그대로 반영된다

**예외 처리**

- 미리보기 영역은 제스처를 받지 않는다. 드래그·핀치 입력은 전부 무시한다.
- **저장 실패 시** UI를 변경 전 상태로 롤백하고 Undo 스택에서도 제거한 뒤 오류 토스트를 표시한다. (즉시 적용 방식이므로 화면과 DB가 어긋나면 안 된다)
- 스택이 빈 상태에서 되돌리기를 탭하면 아무 동작도 하지 않는다 (버튼이 이미 비활성).
- 해금된 아이템이 마스터에 없거나 에셋 로드에 실패하면 해당 슬롯을 기본 아이템으로 대체하고, 그리드에서 해당 칸을 숨긴다 (빈 화면 방지).
- 되돌리기로 복원할 아이템이 그사이 유효하지 않게 된 경우(P3 유료 아이템 환불 등)는 해당 스택 항목을 건너뛴다.

**AC**

- [ ] 아이템 1탭으로 해당 부위만 교체되고 미리보기에 즉시 반영된다
- [ ] 다른 부위(눈을 바꿀 때 코·입 등)는 영향을 받지 않는다
- [ ] 같은 카테고리의 다른 아이템을 탭하면 기존 아이템과 교체된다 (중복 장착 없음)
- [ ] 코·볼·머리장식은 `🚫 없음`으로 해제할 수 있고, 눈·입에는 해제 옵션이 없다
- [ ] **미리보기를 드래그·핀치해도 아무 변화가 없다**
- [ ] 모든 부위가 항상 정해진 위치에 정렬되어 표시된다 (어떤 조합에서도 어긋남 없음)
- [ ] 화분의 성장 단계가 1→5로 바뀌어도 눈·코·입·볼·머리장식의 위치가 변하지 않는다
- [ ] 5단계 개화 시 머리장식이 꽃을 가리지 않는다
- [ ] 렌더링 순서가 배경→화분→식물→볼→입→코→눈→머리장식 순으로 정확하다
- [ ] 현재 장착 중인 아이템이 그리드에서 선택 상태로 표시된다
- [ ] 미해금 아이템 탭 시 교체되지 않고 해금 조건이 안내된다
- [ ] 앱 재실행 후에도 꾸민 상태가 유지된다

*즉시 적용 · 되돌리기*

- [ ] 아이템을 탭한 즉시 저장되며, **저장 버튼 없이 뒤로가기만 해도 메인 화면에 반영된다**
- [ ] 뒤로가기 시 확인 다이얼로그가 **뜨지 않는다**
- [ ] 진입 직후 되돌리기 버튼이 비활성(투명도 40%) 상태다
- [ ] 아이템을 1회 교체하면 되돌리기 버튼이 활성화된다
- [ ] 되돌리기 1탭으로 마지막 변경만 원복되고, 그 이전 변경은 유지된다
- [ ] 되돌리기를 반복해 끝까지 누르면 진입 시점 상태로 돌아가고 버튼이 다시 비활성화된다
- [ ] 되돌리기 후 앱을 재실행해도 되돌려진 상태가 유지된다 (되돌리기도 저장됨)
- [ ] `🚫 없음` 해제도 되돌리기로 복원된다
- [ ] 미해금 아이템을 탭해도 되돌리기 스택에 쌓이지 않는다
- [ ] S3을 나갔다 다시 들어오면 되돌리기 버튼이 비활성 상태로 초기화된다
- [ ] 20회 넘게 교체한 뒤에도 되돌리기가 정상 동작한다 (최근 20단계까지)
- [ ] 빠르게 연속 탭해도 최종 상태가 정확히 저장된다 (디바운스 후 flush)
- [ ] 첫 진입 시 "고르면 바로 적용돼요" 안내가 1회만 표시된다
- [ ] 360×640 소형 기기와 대형 기기에서 부위 정렬이 동일하게 유지된다

### S4. 통계 화면 — P2

**목적**: 기록의 누적을 시각화하여 지속 동기를 제공한다.

**구성 — 일간 / 주간 / 월간 탭**

| 탭 | 그래프 | 표시 지표 |
|---|---|---|
| 일간 | 시간대별 막대 (0~24시, 2시간 단위) | 오늘 총량, 목표 대비 %, 기록 횟수, 첫/마지막 기록 시각 |
| 주간 | 요일별 막대 (월~일) + 목표선 | 주 평균, 달성일 수, 최다/최소 요일 |
| 월간 | 달력 히트맵 (달성률에 따라 색 농도) | 월 평균, 달성일 수, 최장 연속 달성 |

**동작 명세**

- 좌우 스와이프로 이전/다음 기간 이동. 미래 기간은 이동 불가.
- 데이터가 없는 기간은 빈 상태 안내: *"아직 기록이 없어요"*
- 기록이 3일 미만인 신규 사용자는 주간/월간 탭에 *"3일 이상 기록하면 더 정확한 추이를 볼 수 있어요"* 안내를 표시한다.
- 모든 집계는 Drift(SQLite) 쿼리로 수행한다. 앱단 반복 연산으로 처리하지 않는다.

**AC**

- [ ] 일간 탭에서 오늘의 시간대별 섭취량이 정확히 표시된다
- [ ] 주간 탭에 목표선이 표시되고 달성 요일이 구분된다
- [ ] 월간 히트맵의 달성일 수가 실제 기록과 일치한다
- [ ] 기록이 없는 기간에 빈 상태 안내가 표시된다
- [ ] 미래 기간으로는 이동할 수 없다

**동작 명세**

- 프로필 수정 시 유효성 검사는 S1과 동일 규칙을 적용한다.
- 체중·나이·성별 변경 시, `is_goal_custom = false`이면 목표량을 자동 재계산하고 토스트로 알린다. `true`이면 *"목표량을 다시 계산할까요?"* 확인 후 반영한다.
- 알림 토글 ON 시 OS 권한을 요청한다. 거부 상태면 OS 설정 이동 안내를 표시한다.
- **전체 기록 삭제**는 되돌릴 수 없으므로 2단계 확인(다이얼로그 + "삭제" 문구 직접 입력 또는 재확인)을 거친다.

**AC**

- [ ] 알림 토글 ON 시 권한 요청이 발생하고, 설정한 시간대에 알림이 도착한다
- [ ] 목표 달성 후에는 당일 남은 알림이 오지 않는다
- [ ] 물을 기록하면 다음 알림 시각이 재계산된다
- [ ] 체중 변경 시 목표량이 재계산된다 (직접 설정 상태가 아닐 때)
- [ ] 내보낸 파일을 가져오기로 복원하면 기록이 동일하게 복구된다
- [ ] 전체 삭제는 2단계 확인 후에만 실행된다
- [ ] 설정의 "기본 컵" 행에 현재 기본 컵과 용량이 표시되고, 탭하면 S5-1로 이동한다

### S5-1. 기본 컵 설정 — P1

**목적**: 짧게 탭할 때 기록되는 컵과, 컵별 용량을 정한다.

**진입/이탈**: S5 > 기본 컵, 또는 S2 기록 시트의 "용량 수정". 뒤로가기로 직전 화면에 복귀한다. **저장 버튼 없이 즉시 적용**한다 (S3와 같은 원칙).

**구성 요소**

| 요소 | 내용 | 동작 |
|---|---|---|
| 안내 문구 | 짧게 탭 시 기록되는 컵을 고르는 화면임을 설명 | 표시 전용 |
| 컵 행 ×4 | 라디오 + 컵 아이콘 + 이름 + 기본값 안내 + `−` 용량 `+` | 행 선택 시 기본 컵 즉시 변경. 선택된 행은 강조 테두리 |
| 용량 조절 | `−` / `+` 50ml 단위 증감 | 10~2,000ml 범위에서 경계값 고정. 용량 숫자 탭 시 숫자 직접 입력 (10ml 단위) |
| 기타 행 | 기본 350ml, "직접 정한 양" 안내 | 나머지 3종과 동일하게 용량 수정 |
| 범위 안내 | `용량 설정 범위 10 ~ 2,000ml (10ml 단위)` | 표시 전용 |
| 현재 설정 카드 | `짧게 탭하면 {컵 이름} {용량}ml가 기록돼요` + `기록은 ml로 저장되어 통계와 목표 계산은 그대로예요` | 변경 즉시 갱신 |

**예외 처리**

- 범위를 벗어난 직접 입력은 저장을 막고 *"10~2,000ml 사이로 입력해 주세요"* 를 표시한다.
- 10ml 단위가 아닌 값을 입력하면 10ml 단위로 반올림하여 저장하고 입력창에 반영한다.
- 저장 실패 시 이전 값으로 롤백하고 오류 토스트를 표시한다.

**AC**

- [ ] 컵 행을 탭하면 기본 컵이 즉시 바뀌고, 뒤로가기 후 메인 버튼의 컵 이름·용량에 반영된다
- [ ] −/+ 로 50ml씩 증감되며 10ml 미만, 2,000ml 초과로는 내려가거나 올라가지 않는다
- [ ] 용량을 직접 입력할 수 있고, 범위를 벗어나면 저장이 차단되고 오류 문구가 표시된다
- [ ] 기본이 아닌 컵의 용량을 수정해도 현재 기본 컵과 메인 버튼 표시는 바뀌지 않는다
- [ ] 앱을 재실행해도 기본 컵과 컵별 용량이 유지된다
- [ ] 저장 버튼과 확인 다이얼로그가 없다

## 11. 수익모델 제안

현재 미정 상태이므로 선택지와 권고안을 제시한다.

### 11.1 옵션 비교

| 옵션 | 방식 | 장점 | 단점 |
|---|---|---|---|
| **A. 꾸미기 아이템 IAP** | 테마 팩 단위 판매 (3,000~5,000원, 영구 해금) | 앱 컨셉과 가장 자연스럽게 결합. 코어 기능은 무료 유지 | 지속적인 신규 아이템 제작 부담 |
| **B. 구독** | 월 2,900원 — 전체 아이템 + 통계 무제한 + 광고 제거 | 예측 가능한 수익 | 물마시기 앱에 월 구독은 사용자 저항이 큼 |
| **C. 리워드 광고** | 광고 시청 시 아이템 해금 티켓 지급 | 무과금 사용자도 수익화. 선택형이라 거부감 낮음 | 광고 SDK 유지보수, 수익 단가 낮음 |
| **D. 배너 광고** | 화면 상·하단 상시 노출 | 구현 간단 | **비추천.** 꾸미기 감성을 정면으로 훼손하고 리텐션을 떨어뜨림 |

### 11.2 권고안

**1.0 출시 시점에는 수익모델을 넣지 않는다.**

근거: 습관 앱은 **리텐션이 검증되지 않으면 어떤 과금 모델도 작동하지 않는다.** D7 리텐션 25% 미달 상태에서 과금을 붙이면 수익도 안 나고 이탈만 가속된다.

**단계별 도입 로드맵**

| 단계 | 시점 | 조치 |
|---|---|---|
| 1.0 | 출시 | 전 기능 무료. **DB에 `is_premium` 컬럼만 미리 확보** (향후 마이그레이션 부담 제거) |
| 1.1 | D7 리텐션 25% 달성 확인 후 | **옵션 A** 도입 — 시즌 테마 팩(봄·여름 등) 판매. 기존 무료 아이템은 계속 무료 유지 |
| 1.2 | A의 구매 전환율 확인 후 | **옵션 C** 병행 — 광고 시청으로 유료 아이템 1개 해금 티켓 지급 |
| 이후 | 아이템 수가 30종 이상 확보되면 | **옵션 B** 검토 — 전체 해금 구독 |

**절대 원칙**: 기록·알림·기본 통계·기본 꾸미기는 **영구 무료**로 유지한다. 페이월을 코어 기능에 두면 앱의 존재 이유가 사라진다.

## 부록 A. 용어 정의

| 용어 | 정의 |
|---|---|
| 달성률 | 오늘 누적 음수량 ÷ 일일 목표량 |
| 스트릭 | 목표를 100% 달성한 날이 연속으로 이어진 일수 |
| 슬롯 | 꾸미기 아이템이 장착되는 위치 단위. 카테고리 = 슬롯 (눈, 코, 입, 볼, 머리장식 등) |
| 앵커 | 각 부위가 놓이는 고정 좌표. 화분(용기) 기준 정규화 좌표로 정의 |
| 즉시 적용 | 아이템 탭 시 미리보기 반영과 저장이 동시에 일어나는 방식. 저장 버튼이 없다 |
| Undo 스택 | 꾸미기 화면 진입 후의 변경 이력. 되돌리기 버튼이 이 스택을 1건씩 pop 한다 |
| 해금 | 조건 달성으로 아이템 사용 권한을 획득하는 것 |
| 쿨다운 | 기록 직후 버튼이 비활성화되는 1.2초 구간 |
| 묶음 기록 | 용량 × 잔 수를 지정해 여러 건을 한 번에 저장하는 기능 |
| 기본 컵 | 짧게 탭할 때 기록되는 컵. 종이컵·머그컵·텀블러·기타 중 하나이며 컵별 용량을 수정할 수 있다 |
| 컵 프리셋 | 컵 종류별로 미리 정해 둔 ml 값. 저장은 항상 ml로 하고 컵은 선택 UI일 뿐이다 |
| 정원 | (P3) 목표 달성일의 화분을 보관하는 공간 |
